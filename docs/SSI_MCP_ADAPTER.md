# SSI MCP for FinQuery: OAuth user connection, read-only research

## Verified facts (8 October 2026)
- The user's connected SSI MCP plugin in ChatGPT has returned real SSI indicators, company profile and company news.
- SSI advertises MCP resource https://mcp.ssi.com.vn/mcp, OAuth metadata at https://mcp.ssi.com.vn/.well-known/oauth-authorization-server and dynamic client registration at https://mcp.ssi.com.vn/oauth/register (public metadata probed in GitHub CI).
- A ChatGPT-connected OAuth session **is not** a token usable by the FinQuery website.
- Public SSI MCP terms describe individual SSI-account holders using MCP clients; do not republish/cross-license SSI bulk data, and verify commercial/public app rights before broader release.

## Architecture
- Static FinQuery website: financial-report/frontend and build_cdn.py (Github Pages works without SSI).
- Web API (requires a same-origin hosting platform with serverless Functions, e.g. a Vercel deployment): api/ssi-auth.js, api/ssi-callback.js, api/ssi-mcp.js.
- Backend helpers: lib/ssi-session.js, lib/ssi-oauth.js, lib/ssi-transport.js.
- OAuth authorization code + PKCE and dynamic client registration. Redirect to official SSI login; passwords and OTP never touch FinQuery.
- AES-256-GCM encrypted HttpOnly, Secure, SameSite=Lax, 7-day browser cookie. Per-user token exchange and refresh only on server. Never return tokens to JavaScript.
- Only read-only allowed tools profile/indicators/news/peers/events. A bounded response is normalized; company news matches exact requested symbol and strips HTML.
- MCP client sends initialize, initialized, tools/list, tools/call; refuses tool schemas with missing or unknown mandatory args.
- Dolphin Research Agent calls it as optional evidence only when OAuth status is enabled and connected. Existing FinQuery prices, intraday, risk, scanners, forecast and historical append-only pipelines are untouched.

## Hosting and environment
GitHub Pages **cannot run api/*.js** and therefore cannot host SSI OAuth. To test, deploy the repository on a same-origin serverless host with root project directory and static outputDirectory financial-report. The compiled financial-report/index.html is generated by python3 financial-report/scripts/build_cdn.py.

Environment variables, server-side only:
- FINQUERY_SSI_ENABLED=1 (defaults off)
- FINQUERY_SSI_SITE_ORIGIN=https://<exact-authorized-website-host> (required; must equal request Host)
- FINQUERY_SSI_COOKIE_KEY=<64 lowercase hex chars from 32 cryptographically random bytes>
- FINQUERY_SSI_CLIENT_ID=<optional stable OAuth DCR client ID; otherwise registration is attempted on each new login>

**Never** add these to committed files, browser JavaScript, static pages or GitHub Actions output; the cookie key must be configured in the hosting provider secret store. Do not use SSI access tokens acquired through ChatGPT plugins.

## User flow
1. Open the *serverless-hosted* FinQuery website and enter Dolphin AI.
2. If SSI backend is enabled, a card "SSI MCP · Bằng chứng doanh nghiệp" appears. Click "Kết nối SSI".
3. The server registers a public OAuth client, initiates authorization with PKCE, and redirects to SSI.
4. Sign in ONLY on the official SSI page and approve read-only access.
5. On return, the SSI panel displays "Đã kết nối SSI"; when asking for fundamental/peer/company analysis, the Research Agent reads SSI evidence optionally.
6. Click "Ngắt SSI" to remove the FinQuery local session; revoke on SSI separately if required.

## Release gates
- CI backend and browser tests green, compiled bundle contains FinSSI but no secret keys.
- Auth redirect, callback, refresh, session revocation tested on a real same-origin deployment with a voluntary SSI login.
- Verify tool schema and reported quarter/date, no hallucinated financial numbers.
- Failover: SSI errors do not block Dolphin, price, charts, Scanner or Forecast; only SSI evidence omitted.
- Confirm terms for usage by a user-facing public app before enabling beyond private preview.

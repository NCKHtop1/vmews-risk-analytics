# Gemini-only external live data

## Target architecture

VMEWS uses **Gemini API + Google Search grounding as the single external live information provider**. Existing versioned model, validation and point-in-time research artifacts stay in the repository and are not regenerated by an LLM.

This separation is deliberate:

- **Live/current external context:** Gemini API with Google Search grounding.
- **Historical/model evidence:** immutable VMEWS repository artifacts.
- **No browser-side Gemini key:** all Gemini calls run in Vercel server functions.
- **No fabricated history:** if a historical value is not available in a versioned VMEWS artifact, the application must mark it unavailable instead of asking Gemini to invent a daily time series.

## Environment variables

Add these only in the server/deployment environment:

```text
GEMINI_API_KEY=<provided later>
GEMINI_MODEL=gemini-3.6-flash
```

Never put the real key in GitHub source, `.env.example`, HTML or browser JavaScript.

## Endpoints

### `GET /api/gemini?mode=market`

Returns Gemini-grounded current VN-Index and cross-asset context with citations.

### `GET /api/gemini?mode=news&symbol=FPT`

Returns recent, de-duplicated material news for a symbol with structured sentiment/materiality fields and grounding citations.

### `GET /api/gemini?mode=stock&symbol=FPT`

Returns current verified quote/fundamental context when search evidence is available. Unknown values are `null`.

### `GET /api/market`

The old Yahoo adapter is replaced by the Gemini-grounded market endpoint. The endpoint intentionally does not ask Gemini to synthesize multi-year OHLCV rows.

## Cutover checklist

1. Add `GEMINI_API_KEY` to the deployment environment.
2. Keep `GEMINI_MODEL=gemini-3.6-flash` unless deliberately changing the model.
3. Test `/api/gemini?mode=market` and confirm citations are returned.
4. Test news and stock modes for at least FPT and PNJ.
5. Verify missing/unverifiable values return `null`, not invented numbers.
6. Merge the migration only after the key is configured.
7. Keep the legacy scheduled market/news refresh workflows manual-only or remove them after the Gemini path is accepted.

## Migration boundary

This branch prepares and switches the dedicated live market/news provider layer. The older Python research/radar code still exists in the repository for reproducibility and rollback. It should not be treated as the target live-provider architecture. A later cleanup can remove legacy adapters once the Gemini path has been validated with the real key.
